# Examples

Fully fictional applications used as examples for the apply-skill workflow.

## `acme-solutions-architect/`

Persona: **Alex Beispiel** — Solutions Architect with five years of AI infrastructure experience and a parallel workshop-facilitation track. Applying to **Acme GmbH**, a fictional Berlin scale-up.

Files included:

- `stellenanzeige.md` — fictional job posting (Phase 1 input)
- `job-fit-analysis.md` — Phase 2a output
- `anschreiben.md` — Phase 3c cover letter, with adversarial-review note
- `cv.md` — Phase 2c CV in Markdown
- `output/.gitkeep` — placeholder; PDFs are not committed

## What is **not** in here

- Real personal data — every name, number, and company is invented
- PDFs — the skill generates them at runtime via Chrome (preferred) or pandoc (fallback)
- Output HTML — generated by `templates/generate-cvs.js` from the fictional `configs[0]` entry

## Verifying the example end-to-end

```bash
# 1. Resolve placeholder profile
cp -r templates/profile $YOUR_CAREER_DIR/profile
cp templates/metadata.yaml.example $YOUR_CAREER_DIR/metadata.yaml

# 2. Generate the CV HTML
CAREER_DIR=$YOUR_CAREER_DIR node templates/generate-cvs.js

# 3. Open the result in a browser
open $YOUR_CAREER_DIR/applications/acme-solutions-architect/output/CV_*.html
```

If the output still contains `{{PLACEHOLDER}}` tokens, the script prints a warning — fill in the missing fields in `templates/profile/*.md` and re-run.
